# Fix report – T-0078 (shared): U5 CA-IS3050G TXD/RXD pin numbers

Date: 2026-11-03 · Unattended · Scope: shared (lib + `can` sheet on both boards)
Item: T-0076 (CRITICAL, from `docs/reviews/2026-11-03-validate-pdm-4ch.md` C1), owner ruling Q-0052: "yes".

## Pre-check (stop condition)

- `docs/part-facts/C528763.md` (CA-IS305x datasheet v1.10): CA-IS3050G SOIC8-WB pinout is 1 VCC1, **2 RXD, 3 TXD**,
  4 GND1, 5 GND2, 6 CANL, 7 CANH, 8 VCC2 (p. 5, Fig. 6-1/Table 6-1). The CA-IS3052G has 2 = TXD, 3 = RXD (p. 6, Table 6-2).
- JLCPCB listing of C528763: model "CA-IS3050G", Chipanalog, SOIC-8-WB. The part is the 3050G, not the 3052G.
- Neither stop condition applies, so I made the fix.

## What changed (T-0076)

- `lib/ESP32-PDM.kicad_sym`, symbol `CA-IS3050G`: pin TXD number 2 → 3, pin RXD number 3 → 2. Names, electrical types
  (TXD input, RXD output) and pin positions are unchanged, so no wire moved.
- `hardware/pdm-4ch/can.kicad_sch` and `hardware/pdm-hc2/can.kicad_sch`: I made the same change to the
  `ESP32-PDM:CA-IS3050G` lib_symbols cache with a ksch.py script (`$CLAUDE_JOB_DIR/scripts/swap_u5_pins.py`). The two
  sheets are identical apart from the `(project …)` line. Each file has 4 changed lines.
- `docs/design-notes.md` §8.5: corrected the Pinout row ("1 VCC1, 2 RXD, 3 TXD, … (Table 6-1; CA-IS3052G has 2/3 swapped,
  Table 6-2)"). Added a dated line to the Symbol bullet: T-0076 corrected pins 2/3, and R70 stays on TXD (/IO17, now U5.3).
- `hardware/pdm-4ch/STATUS.md` and `hardware/pdm-hc2/STATUS.md`: added a T-0078 entry and set the Updated line.
- Not touched: ARCHITECTURE.md (the pin map IO17 TX / IO18 RX is unchanged), R70, wiring and parts.

## Checks

- Baseline (before): on both boards, U5.2 TXD was on /IO17 (U1.21, R70.2) and U5.3 RXD was on /IO18 (U1.22). ERC gave
  0 errors and 5 warnings (4 × BC817 Q3–Q6 and 1 × USB4145 J3 `lib_symbol_mismatch`).
- After: ERC on both boards gives 0 errors and the same 5 warnings. There is no `lib_symbol_mismatch` on U5.
- Netlist (kicadxml, net-by-net comparison) on both boards. Only two nets differ:
  `/IO17`: U5.2 TXD → **U5.3 TXD**; `/IO18`: U5.3 RXD → **U5.2 RXD**. All other nets and U5 pins 1 and 4–8 are unchanged.
- `tools/fix_check.py --scope shared --refs U5`: **OK**. pdm-4ch has 196 parts (+0) and 61 unique (+0); pdm-hc2 has
  212 parts (+0) and 70 unique (+0).
- Heat budget: not run, because no output changed. There is no cost or LEN effect.

## Open points

- None for this item. CAN on the first prototype should still get the bring-up test already planned (loopback and
  bus traffic).

## Suggestions (not done)

- A check in `/validate` that compares every custom `lib/` symbol's pin names and numbers with its part-facts pinout
  table would catch this class of error early.
