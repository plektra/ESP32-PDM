# Plan T-0258 (2026-11-13, unattended)

Two approved items, both pdm-4ch. Each one goes into a package. Nothing is deferred.

## Packages

**P1 – pdm-4ch routing: maze_route merge fix, ch1/ch4 signal parts toward U1, more maze passes (T-0218, pcb-fixer).**
This package carries out the Q-0073 ruling. First, `maze_route.py` must start a net's later legs from the copper
that is already laid, so it stops laying duplicate copper. Then the ch1/ch4 signal parts move toward U1:
R101/R102/R103/R104/R107/C101/D102 and their 4xx twins. After that, more maze passes run, one build per pass.

The work is layout and script only. It stays inside the decision 172/176/178 limits. R105/D101, the OUT parts and the
VS parts do not move. The start state is 48 unconnected, 0 errors and parity 0.

"In progress" with fewer unconnected items counts as a result. The package stops and asks the owner only if:
- a stage gains nothing, or
- the work would need a one-way door: power copper outlines, connectors, the board outline or the schematic.

**P2 – sync: +3V3 neck wording (T-0257).** This package only rewords text in design-notes (T-0253 note) and in
STATUS.md. The current text says the +3V3 necks feed "only clamp diodes and pull-ups". That claim was never traced.
The new text states the real bound instead:
- the necks are about 3 squares of 0.2 mm copper in total;
- that is a few mΩ (In2 is 0.5 oz, B.Cu is 2 oz);
- the drop is negligible even at 0.5 A.

P2 comes after P1 because P1's re-route can change or remove the two necks, and the text should describe the final
copper.
