# Plan T-0240 – pdm-4ch routing after Q-0071 (In2 corridor, scripted channel buses)

Date: 2026-11-12 · Role: planner (unattended) · Items: 1 (T-0218, owner ruling Q-0071)

## Overview for the owner

**Where it stands.** T-0236 used your Q-0070 ruling, vias through VS-In2 (decision 172), and got the board from 78 to
**74 unconnected**, with 0 DRC errors, parity 0 and every pour whole. Two things block further progress:

- **The west channel nets cannot get out.** They sit in a B.Cu pocket closed by the VS-B copper. A via is no help
  there, because it also needs room on F.Cu and B.Cu (decision 175).
- **The router results are noisy.** Freerouting starts every run from a DSN with 722 built-in violations, and
  single runs vary by about ±3 unconnected.

You ruled on Q-0071: an **In2 corridor**, with signal tracks through the VS copper on In2.Cu only, and routing done
mostly by script.

**Package P1 (pcb-fixer, pdm-4ch)** – one item, five stages in this order:

1. **Clean router export.** Fix the router export so the DSN has no built-in violations, and run several Freerouting
   runs per build. `build_routing.sh` already takes up to 3 runs with different strategies.
2. **Corridor rule in the build scripts.** Signal tracks may run on In2 inside VS-In2. The build checks:
   - VS-In2 stays one island and loses at most 15 % of its baseline area;
   - every PROFET thermal via stays inside VS-In2;
   - the other pours keep the existing ≥ 95 %.
3. **One channel signal bus, repeated.** Design one channel's sense, input and LED bus through the corridor in
   `fixed_routes.py`, then generate the other three channels from the same pattern. The J6 bundle, CAN, USB and the
   U1 fan-out stay fixed routes.
4. **Short links.** Freerouting fills the remaining short links. If it still cannot close them, they are scripted
   too.
5. **Heat budget** at 40 °C (decision 9), then STATUS.md and design-notes.

The report must name T-0218 in its fix block from the first minutes on, as blocked "in progress" until the board
reaches 0 unconnected. Two earlier runs ended with an empty or unfinished report.

- **Deferred:** none.
- **Decisions:** one new row (Q-0071). It amends decision 172:
  - signal tracks (not only vias) are now allowed through VS-In2;
  - VS-In2 may lose up to 15 % of its area, where 172 allowed 5 %;
  - routing becomes script-first.
- **Planner finding (MINOR, tool):** the T-0236 merge commit says "0 fixed, 0 blocked", but its fix block lists
  T-0218 as blocked. The orchestrator's merge summary under-counts blocked items. This does not affect the plan.

**Safety.** The ruling keeps the F.Cu/B.Cu VS copper, the 16 A paths and the surge path unchanged. The corridor only
thins the In2 VS layer, which carries about 11 % of the load current and sits under the PROFET thermal vias. That is
why P1 checks the area, the island count, the thermal vias and the heat budget. A competent person should review the
battery path, the VS copper and the outputs before installation.
