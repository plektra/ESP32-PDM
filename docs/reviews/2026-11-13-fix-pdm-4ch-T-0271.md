## Step 1–3: the VS-In2 east-edge trim was not applied
The VS-In2 outline lives only in the board file; prep reads it and no script builds it. Its east edge is x 56.5 at
y 4.95–34.5. The B spine is x 45.5/46.5–55.0 at y 5–35, with a 1.0 mm zone clearance.

FINDING (MAJOR): the ruled trim cannot create the exit. The corridor band is drawn **centred on** the VS-In2 outline
(maze_route.py: the outline as a 2 × 1.5 mm line; routing_build.py: outline − deflated outline). An In2 run can
therefore never cross any VS-In2 edge. It can only end at a via at least 1.5 mm inside the pour, which today means
x ≤ 55.0. A through via clears the B spine only at x ≥ 56.3, and for y < 35 every spot in the band-free core is spine
on B and OUT2-F/OUT3-F or U12/U13 on F. Pulling the east edge back 2–3 mm moves the core further west (x ≈ 52–53).
The via column at x 55–57 then sits outside VS-In2, and no corridor run can reach it without crossing the new edge
(a one-way door in this brief). The trim alone gains nothing and would fail the "fewer unconnected" build gate, and
it costs VS-In2 copper, so it was not made. VS-In2 is unchanged.

The exit needs one of these one-way rulings (design-notes 8.21):
- **(a)** One marked exit where pocket In2 runs may cross the VS-In2 east edge at y 5–20 into a via column at
  x 56.3–57. VS-In2 gets a notch and stays one island; the trim becomes optional.
- **(b)** A spine notch: the B spine east edge to x ≤ 53.7 at y 5–20, so a via at x ≈ 55 in the band-free core
  clears it.
- **(c)** Signal vias in the x 46.15 strip between OUT3-F and the spine, as the USB pair has. They notch the spine
  fill. The run then goes east on F between U12 and U13 at y 16.6–19.8 / 21.8–23.
