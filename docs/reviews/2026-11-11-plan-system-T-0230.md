## Overview for the owner

**One item, T-0218.** It covers the pdm-4ch routing that is stuck at 78 unconnected items. Your ruling on Q-0070:
signal vias may pass through VS-In2, and a placement stage may give the U1 block and the channel signal columns more
room. Decision 172 already records that ruling.

This is a re-plan. The first package (T-0226, from plan T-0225) ran into the 5400 s timeout. It wrote no report and
changed nothing in the repo: `POUR_LOSS_MAX` is still 0.02, and the board and scripts are as T-0214/T-0221 left them.
The likely cause is that one session tried the build change, the placement stage, rebuilds and hand-made fixed
routes all at once. Freerouting runs are long.

The orchestrator runs only packages that own an item, so the work cannot be split into three queued packages.
Instead, the new package does the steps in a fixed order:

1. Write the report early.
2. Make the build change and land it.
3. Do the placement and land it.
4. Add fixed routes only if time is left.

After each step it lands whatever is a clean improvement. Within about 75 minutes it stops and reports what is still
open as a two-way blocked item. The orchestrator then queues that rest as a follow-up instead of losing the session.
